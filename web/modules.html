Documentation / Module reference

Laravel modules, from intent to source.

Each module maps to a project file. Saving a missing file uses Laravel's Artisan generator when available, or an AppyHP scaffold for services, repositories and frontend pages. These scaffolds are starting points: describe behavior in the prompt, generate or edit the implementation, and test it in your application.

Graph connections describe architecture and provide AI context. Creating a file does not automatically install a dependency, register middleware, run a migration or start a worker. Complete the Laravel integration described below after reviewing the generated code.

Controllers and middleware

Controller: target app/Http/Controllers/InvoiceController.php, or a nested application namespace. Actions containing create or edit produce a resource controller; API resource actions produce an API controller; __invoke produces an invokable controller. Add your orchestration logic and register the controller in a route.

Middleware: target app/Http/Middleware/EnsureSubscribed.php. Define the check and call the next handler when allowed. Register aliases or groups in the host application's bootstrap/app.php, or use the middleware class directly on a route.

Validate the invoice with StoreInvoiceRequest, authorize creation,
call the connected InvoiceService, and return an InvoiceResource.

Form requests

Target app/Http/Requests/StoreInvoiceRequest.php. Set validation rules and an explicit authorization decision. Laravel's generated request initially denies authorization; implement authorize() before using it. Type-hint the request in the controller and use its validated data.

API resources

Target app/Http/Resources/InvoiceResource.php. Define the public response in toArray() and avoid leaking credentials or internal fields. Return the resource from a controller and use InvoiceResource::collection($invoices) for lists. Include pagination and optional loaded relationships in the prompt.

Eloquent models

Target app/Models/Invoice.php. Describe the table, assignable fields, casts and relationships. Connect models to their table and to the controllers or services using them. Review mass assignment and hidden attributes before accepting user input. A model scaffold does not create its database table automatically.

Tables, migrations, factories and seeders

Table: represents a table-creation migration in database/migrations. Use a unique timestamped filename, such as 2026_10_05_000000_create_invoices_table.php. Describe column types, nullable fields, defaults, foreign keys and indexes. The AI table preview describes the draft, not a live database inspection.

Migration: represents a schema change. Specify the existing table and operation, and review both up() and down(). Create a new migration for a deployed schema instead of editing a migration that has already run.

Factory: target database/factories/InvoiceFactory.php; the filename must end with Factory.php. Set the model and provide realistic fixture attributes. Seeder: target database/seeders/InvoiceSeeder.php, implement run(), and call it from DatabaseSeeder when appropriate.

Review generated migrations before running php artisan migrate. AppyHP does not execute migrations or seeders. Back up important data before applying schema changes.

Services and repositories

Services in app/Services coordinate business operations; repositories in app/Repositories can encapsulate data access where useful. AppyHP creates plain PHP classes because Laravel has no mandatory repository or service base class. Namespaces follow Composer's PSR-4 mappings. Inject concrete classes into controllers; bind interfaces in a service provider when using abstractions.

Jobs, commands, events and listeners

Job: target app/Jobs/ProcessInvoice.php and implement handle(). Define retries, timeouts and idempotency for work that may run more than once. Configure the queue connection and run php artisan queue:work for asynchronous processing.

Command: target app/Console/Commands/SyncInvoices.php. Review the signature, arguments, options and exit status. Schedule recurring execution in routes/console.php and configure Laravel's scheduler on the server.

Event: target app/Events/InvoicePaid.php and describe its payload. Listener: target app/Listeners/SendInvoiceReceipt.php, specify the event and whether it should be queued, then implement its handler. Verify discovery with php artisan event:list; register unusual listener locations explicitly.

Policies and authentication

Policy: target app/Policies/InvoicePolicy.php and optionally identify the model. Implement each authorization rule and call it through a controller, gate or route. Keep the conventional model-policy naming for discovery, or register the mapping explicitly.

Auth: targets config/auth.php using Laravel's configuration publisher. Review guards, providers and password brokers. This module configures authentication; it does not install login screens or a starter kit. Existing configuration files are preserved until you explicitly edit or publish a draft.

Blade views, components and Inertia

View: target resources/views/invoices/index.blade.php, then render it with view('invoices.index', $data). Escape user content using Blade's regular echo syntax.

Component: target app/View/Components/InvoiceCard.php. AppyHP requests an inline component scaffold so creating a class only writes the chosen file. Move the template to a Blade view yourself if preferred.

Inertia Page: target resources/js/Pages/Invoices/Index.vue, .jsx/.tsx for React, or .svelte. The module inherits the workflow frontend unless overridden. Install the matching Inertia client adapter, configure page resolution and Vite, and return Inertia::render('Invoices/Index', $props) from the controller.

Inertia Middleware: target app/Http/Middleware/HandleInertiaRequests.php. Install inertiajs/inertia-laravel, configure its root Blade view and shared props, and append the middleware to your web group in bootstrap/app.php. A scaffold can be prepared before the adapter is installed, but requires it to run.

Notifications and mail

Notification: target app/Notifications/InvoicePaidNotification.php. Choose delivery channels and define their messages. The recipient needs Laravel's notification support; database notifications also require the notifications table.

Mail: target app/Mail/InvoiceReceipt.php. Define envelope, content and any attachment handling. Configure the host application's mail transport and use a local log or testing transport while developing. Queue delivery when appropriate and test it with Laravel's notification or mail fakes.

Queue, cache and storage

These modules publish Laravel's config/queue.php, config/cache.php and config/filesystems.php. Keep environment-specific credentials in environment variables. Provision each backend before using it; database queues and caches need their tables, while Redis needs a running service.

Use private disks for sensitive files, and create a public storage link only for content intended to be public. After changing configuration, clear or rebuild the host application's configuration cache. Studio uses its own file sessions and file-backed AI throttle, so it can open before database setup.

Finish and verify your implementation

  1. Check the target path and the complete generated source.
  2. Save the draft, then review the changes in Git.
  3. Register required routes, middleware or bindings in Laravel.
  4. Run your application's tests, migrations and frontend build as appropriate.
  5. Keep AppyHP installed as a development dependency and disabled on public production deployments.
